Verdict

The app now reads as one product. Every area has one name in the sidebar, on the phone bar and in the top bar. Actions say what they do, and red means "do this" or "careful". Menus, confirms, the period picker and toolbars behave the same on every page. Layouts hold together in light and dark, on desktop, tablet and phone. To reach 18 or more out of 20: test the non-admin roles, re-measure load times, and move the remaining styling into classes where the values allow it.

Biggest fixes

  1. Production report works again. Before, the query called .catch(), which Supabase queries don't have, so the page crashed every time.
  2. Counts agree. The Dashboard shows "Recent orders" with "All active orders (2)", matching the Orders page. The sidebar badge counts steps waiting on you.
  3. Phone toolbars fit. Search comes first and full width, filters wrap inside the card, and New quotation floats above the tab bar.
  4. Words and one name per area. Tabs and row actions are labelled. Dashboard, Orders, Purchasing, Production, Inventory, Reports and Settings mean the same everywhere.
  5. Red only for actions and danger. Links and charts are blue, totals and roles neutral, and focus rings solid. The missing colour variables are defined, and every menu closes on Esc.

1 · Broken or blocked

P0Fixednew

Reports → Production crashes

The page always shows “This page couldn't load”. The server error is: db(...).from(...).select(...).gte(...).lte(...).order(...).catch is not a function. Supabase query builders can be awaited but don't have .catch, so the page throws before it renders. Lines 29 and 37 use the same pattern and only work because they wrap a promise.

Wrap each query in try { await … } catch { … }, or use .then(r => r, () => ({ data: [] })).

app/production/reports/page.js:45

P1Fixed

Counts disagree between Dashboard, sidebar and Orders

The Dashboard “Active Orders” table lists Q-2026-004, 005 and 006, but both links above it say (2). The sidebar badge says 3, and the Orders page says All Active 2 / Everything 3.

Define “active” once (in batchQueues()) and use that number for the badge, the links and the table. Or rename the dashboard table to “Recent orders”.

app/page.js · app/orders/page.js · lib/server.js

P1Fixed

Five CSS variables used but never defined

--danger falls back to #ef4444, which matches neither theme's red. --surface-sunken, --radius, --ink and --text-muted have no fallback, so those boxes get no background or radius. Affected: the BOM dialog and calculator, New Recipe, the inventory page, the DPR form and dialog, and production reports.

Map them to existing tokens: --danger → --red, --surface-sunken → --fill-2, --radius → --r-ctl, --text-muted → --muted, --ink → --text.

P2Fixednew

Theme loader is a React <script>; the error page lost dark mode

The console shows “Encountered a script tag while rendering React component”. On the crashed Production report, the page rendered in light theme while the saved setting was dark. The console also shows “Transition was aborted because of invalid state” from the theme switch animation.

Load theme-init.js with next/script using strategy="beforeInteractive" (or inline it in <head> outside React). Wrap startViewTransition in a try/catch.

6 · Typography and colour

P1Fixed

Red means brand, link, progress, money, role and error

Keep red for the logo, one primary button per screen, and danger. Show links and quote numbers in text colour, the current step as a neutral outline, totals as bold neutral text, and roles as neutral chips.

P2Fixed

21 font sizes, 13 px body, 10–11 px labels

The UI/UX Pro Max guidance asks for at least 16 px body text on phones (the app already sets inputs to 16 px) and a fixed scale. On desktop the app uses 13 px for body text, and table headers go down to 10 px.

Six size tokens (11 / 12 / 14 / 16 / 20 / 26), a 14 px desktop body, 15–16 px on phones, three weights, and no inline fontSize.

P2Fixed

466 inline styles; faint focus ring

About 10 utility classes in place of inline styles, and outline: 2px solid var(--accentH); outline-offset: 2px for every focus ring.

P3Fixed

About the design-system recommendation

The UI/UX Pro Max database suggested a navy-and-blue “vibrant block” style with Fira Sans for this product type. That doesn't fit here: the red FMS look was chosen by you, and that choice wins. The one part worth borrowing is its dense-dashboard spacing (8–32 px) as a consistent spacing scale.

7 · Animation and motion

P2Fixed

Every page slides in after navigation

About 250 ms of fade-and-lift on every click undoes the feeling of speed from the recent performance work. The guidance used here is to animate one or two meaningful things per view, and a whole page is not one of them.

Remove contentIn. Keep motion for dialogs, sheets, menus and toasts; their timings (250 ms in, 170 ms out) are already good.

P3Fixed

transition: all; reduced motion removes every cue

List the properties that change explicitly. Under reduced motion, keep a 120 ms opacity fade on dialogs and sheets.

Not covered

Only the Admin login was used, so role-specific screens were inferred from code and route rules. The login page was read from code only. No form was submitted, so success toasts, server error messages and the plant “Mark ready” and dispatch flows weren't exercised. Tablet widths (768 and 1024 px) were tested in the re-audit. Landscape phone and the largest system text size were not. Touch gestures, such as dragging a sheet down to close it, were checked in code, not on a device.

What's working

  • Native dialogs with focus trap, Esc, a closing animation and an unsaved-changes guard.
  • Phone tables become cards, labelled from the column headers.
  • Correct phone keyboards: numeric and decimal input modes on quantity, size and price fields.
  • Long lists load 50 at a time (Materials: 2,203 rows).
  • Guarded deletes: confirm before removing an item value; type-to-confirm on big deletes; Undo dispatch asks first.
  • Useful empty states, for example “View Dispatched (3) →”.
  • Error page with recovery: “Try again” and “Back to Orders”, plus a reference number.
  • 44 px touch targets, 16 px inputs on phones, and no sideways page scroll at 375 px.
  • Make PI dialog: pre-filled quantities and clear wording.
